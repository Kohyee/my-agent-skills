# English-learning-manager

统一管理 `E:\英语` 的既有学习文件。根目录 `AGENTS.md` 是项目总规则；路径和真实学习记录在 `.learning-manager/state.json`。本 Skill 的唯一源码在项目内，个人技能目录通过目录联接指向它，避免维护两套系统。

首先读项目 AGENTS 和 [数据规范](references/data-contract.md)。只在相关操作时读 [操作流程](references/workflows.md)。使用工作区打包的Python运行 [manager.py](scripts/manager.py)，不要为用户安装新Python或要求用户手工执行代码。默认项目根路径由脚本位置推导；隔离测试必须显式传 `--root`。

## 自然语言分流

| 用户意图（含近义表达） | 执行动作 |
|---|---|
| 开始今日学习、生成 Day N、给我今天的练习 | `context`读取档案/当日计划/近期反馈/到期错题 → 调用原Worksheet Skill → 验证并`register`，自动同步独立单词汇总Word并渲染检查 |
| 批改今日作业、看看这些答案、改一下这张手写卷 | 保存并转录原输入 → 逐题教学批改 → `grade` → 每日反馈与错题自动重建 |
| 调整今天的学习内容、今天只学30分钟、改练阅读 | 将自然语言转成四训练格和总分钟 → `adjust`同步原周表与执行日志 |
| 今天没有完成、只做了一部分 | 根据已知事实记录`partial`/`missed`及实际内容；缺少实际分钟等信息时收集必要缺项；不改其他日期 |
| 复习错题、巩固上次错误 | `due` → 优先重复错误 → 在当天原有时长内替换题目，出卷时登记复习题号映射 |
| 本周总结、这周学得怎样 | `weekly` → 按实际证据生成历史评估、更新档案末尾最新评估索引 |
| 开始下一周、安排下周 | 先评估上一周 → 结合原有下周表、薄弱点和真实执行制定7天计划 → `plan-week`复用已有周表或克隆原周表延展 |
| 查看学习进度、我现在掌握怎样 | `progress`，解释检测证据和未评估项目，不用文件数量代替学习完成量 |
| 记录重点、这个很重要帮我记下、把这些搭配整理进重点 | `points`读取已有条目和Word → 按[重点记录流程](references/key-points.md)分类、合并和讲解 → `record-points`事务更新同一份重点Word |
| 生成单词汇总、更新词汇汇总、把每天新增20词单独整理 | 按[单词汇总流程](references/vocabulary-summary.md)，`summarize-vocabulary`按日期与Day更新独立Word；`vocabulary`读取，复习词与重复词不计新增 |

这些是意图示例，不以精确字符串匹配；“先批改，再把明天改为冠词训练”应顺序完成两个操作。用户指定的日期优先。只有日期或作业身份确实存在冲突才询问，不以猜测解决冲突。

## 必须保持的边界

- 不改、不重建已有 `English-learning-template`。每次出卷先读其SKILL、`artifact-template.json`、最新design-spec和保留参考，用documents模板流程克隆出卷；原有排版、命名和题型要求继续适用。
- 默认60分钟，用户明确调整才改；四训练格的分钟合计必须一致。复习在原有预算内替换；周末仅用旧词。计划与模板章节不一致，向原技能传明确的局部安排，未布置模块不增加必做任务。
- 作业批改由Codex按原题和真实答案判断。脚本只校验与保存，不能把OCR或精确字符串匹配当作开放题评分器。手写字迹不清楚记pending，指明需确认的题号；不能补字猜答。
- 同日一份当前试卷/批改记录、Day全局唯一。重批更新当前版本，统计重新汇总，保留事务版本。已有作答后不更换试卷题目。
- 先读取文件，重要修改自动备份。已完成历史计划冻结；缺乏证据不填造完成记录、用时或能力成绩。
- 只把真实作答写入正式根目录。联动测试放到 `work/learning-manager-qa/sandbox-*`，测试生成物不进入真实学习统计。
- 重点保留原文、双语例句、必要提醒及首次收录日期，同一知识点复用稳定标识，重复内容不新增；收录不构成检测证据或已掌握状态，不改变学习任务完成量。

每次写入后运行 `audit`。出卷结构通过但无法逐页渲染时只能登记draft，说明限制。结束时简要列出生成/更新文件、学习问题及下一次重点；不要把内部JSON和脚本当成学习者必须操作的产品界面。
