# 分类重点记录

在用户说“记录重点”“这个很重要帮我记下”“整理进重点文件”等时使用。学习者直接发送自然语言，不需要填写字段或运行命令。

## 收录

1. 运行 `manager.py points` 并读取其 `document_path` 指向的现有 Word；首次收录尚无文件时创建 `06_Learning Notes/English Learning_Key Points.docx`。这是唯一持续维护的重点文件。
2. 理解用户内容，选“词汇与搭配、语法与句型、易混辨析、常见错误”之一及合适子分类。按知识点归类，子分类可扩展；只显示有内容的分类。例如 `require doing`、`consider doing sth`、`suggest doing sth` 归“词汇与搭配 → 动词后接 doing”。
3. 先比较现有条目的含义和搭配，语义相同的复用其 id。标识不随标题措辞变化；不同用法可另立条目。脚本阻止相同搭配重复标识；近义去重由Codex结合上下文判断。
4. 原文逐字保留，另写整理后的搭配、中文含义、一条自然英文例句及中文翻译、必要提醒。纠错写在整理与提醒中，不悄悄改写原文。不确定的表达先核对；无法辨认的文字先待确认，不猜。
5. 用 `record-points --input <JSON绝对路径>` 保存。日期按用户明确日期或当前Asia/Shanghai日期填写。输入档案与 Word、state 一起事务写入；完全重复的输入返回 unchanged，不改记录、日期或Word。
6. 逐页渲染、检查更新后的实际 Word，然后运行 audit。反馈新增/补充数量、分类和文件链接；发现已有审计问题时区分本次新增问题。

用户已精简重点Word时保留其显示偏好。`display_fields`可关闭original、translation、first_recorded_date在Word中的显示；内部原文、双语例句和首次日期仍完整保留。不要因为再次收录就恢复用户主动删除的显示字段。

## 输入格式

JSON由Codex构建。`date`为收录日期，`raw_input`为完整原始输入，`entries`为列表。每条包含：

| 字段 | 作用 |
|---|---|
| id | 稳定小写标识，首次创建、以后复用，如 collocation.consider-doing |
| category | 大类与子分类列表，如 ["词汇与搭配", "动词后接 doing"] |
| original | 本条用户原文，必须原样出现在raw_input中 |
| pattern | 整理后的搭配或知识点标题 |
| meaning | 中文含义；可修正用户表达，但原文仍保留 |
| examples | 至少一条 {"english": "英文例句", "chinese": "中文翻译"} |
| notes | 用法提醒列表，可为空 |

重复id更新整理后的标题、分类和含义，例句和提醒去重合并；原文存在则不重复归档。首次日期不变；新原文及更正前版本分别在来源档案、事务快照中保留。需要纠正已有例句或删除误收内容时，先读取当前记录，明确修订目标并通过事务保存修订，不用另建近义id绕过。

## 文件与证据边界

数据为统一state中的可选 `key_points` 集合；旧项目首次收录时添加，不改变原学习记录。`points`只读展示条目；`record-points`触发事务。审计检查唯一标识、原文归档和Word校验值。

重要文件写入前留存完整字节备份。后续更新 Word 复用其样式和页面配置，其他ZIP部件逐字节保留；如果文件被手工编辑或原文被修改，脚本停止写入。先读取并合并编辑，不直接改校验值绕过保护。手工合并应保留所有无关内容与排版，并在同一事务更新Word和对应重点数据。

重点仅表示用户认为重要，不自动写入knowledge、作答checks、错题、周成绩、完成量或复习日程。实际作答后的评估仍走原批改流程。普通语法问答不自动收录；用户明确说记录或确认收录才保存。
